1. Single-Flight Token Refresh Pattern

Zero Race Conditions

Quando múltiplas queries paralelas no TanStack Query retornam HTTP 401 Unauthorized simultaneamente (ex: ao abrir o dashboard com 6 cards), o interceptor enfileira as requisições pendentes em memória e dispara um único POST para renovação:

// Interceptor de Resposta Axios/Fetch:
let isRefreshing = false;
let failedQueue: Array<{ resolve, reject }> = [];
if (status === 401 && !originalRequest._retry) {
if (isRefreshing) return queueRequest(originalRequest);
originalRequest._retry = true;
await post('/_api/auth/token/refresh/');
processQueue(null, newAccessToken);
return retry(originalRequest);
}
Garante que o backend nunca receba rajadas concorrentes de refresh token inválidas.

2. Proxy Reverso `/_api` & Proteção CSRF

Same-Origin Security

O Next.js App Router atua como proxy reverso roteando /_api/:path* diretamente para o servidor Django DRF no mesmo host. Não há necessidade de habilitar CORS irrestrito em produção.

// Cookies Gerenciados com Restrição Estrita:
dt_ticket_access: httpOnly, SameSite=Lax, Secure
dt_ticket_refresh: httpOnly, SameSite=Lax, Secure
dt_ticket_csrftoken: Readable by JS, SameSite=Lax
// Injeção em Cabeçalho DRF:
headers['X-CSRFToken'] = getCookie('dt_ticket_csrftoken');
Bloqueia ataques Cross-Site Request Forgery em todos os formulários e chamadas REST.

3. Matriz de Autenticação Híbrida (`AUTH_MODE`)

Configurável por Ambiente

O backend implementa o padrão de autenticação híbrida controlada via variável de ambiente AUTH_MODE:

AUTH_MODE Origem Primária Fallback Uso Típico
both Semantix HubAPI (OAuth2) Sessão Local SQL Server Produção Corporativa
hub Semantix HubAPI Exclusivo Nenhum Staging & Integração SSO
session Django DB Auth Local Nenhum Dev Local & Testes Offline
Permite operação ininterrupta do sistema mesmo em manutenções temporárias do HubAPI corporativo.

4. Cache de Alta Performance SHA-256 (TTL 45s)

Alívio do SQL Server

Para impedir o "query storm" no banco de dados a cada clique na UI, o usuário autenticado e suas permissões ativas nos 9 módulos são cacheados em memória:

// Chave de Cache Criptográfica:
cache_key = f"pbac_user_{sha256(user_id + token_secret).hexdigest()[:16]}"
cached_profile = cache.get(cache_key)
if not cached_profile:
cached_profile = load_user_and_permissions(user_id)
cache.set(cache_key, cached_profile, timeout=45)
Qualquer alteração de perfil em `ModulePermission` invalida a chave de cache imediatamente via signals.
